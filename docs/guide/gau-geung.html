Gau Geung, the team mode

Run a team of agents from mogeung: four CLIs in four worktrees, telling each other what they did, with you holding the budget and the switch.

built 2026-10-10 on branch gau-geung · every part is awaiting its first real boot

What Gau Geung is

mogeung watches the sessions you run and tells you which one needs you. It never starts, steers or stops an agent it did not start itself. Gau Geung is the one place it does start them: a team is a named set of seats, each seat an agent CLI the daemon launches in a tmux pane of its own, in a worktree of its own, configured by flags at launch. A seat is owned: mogeung may send to it, wake it, watch it, restart it and stop it. Every session you start by hand stays exactly as it was: observed, never touched.

The vocabulary the window uses, and this guide keeps:

wordmeaning
seatan agent the daemon started from a team definition, in Gau Geung mode
teama named set of seats with one policy, one pause switch and one budget
observedany session the daemon merely found: yours, untouched
hopone delivery from an agent to an agent with no human between
hooked / plainwhether a seat's own hooks reach the daemon, or it is known from its transcript and its screen only
helda send the policy kept for you instead of typing it

Before you start

  • tmux on the daemon's machine. No tmux, no seats.
  • curl, so a seat's hooks and its mogeung-send command can reach the daemon. Without it a seat still runs, but is plain and cannot talk to its teammates.
  • A git repository for the team to work in. Each seat gets a worktree of it unless you say otherwise.
  • At least one of the four CLIs on PATH: Claude Code, Codex, Qwen Code, opencode.
  • For handovers only: a model endpoint in ~/.mogeung/config.toml (model_url, and allow_remote_model if it is not on this machine). Without one, seats start without a handover and the log says so.
Running the branchGau Geung lives on branch gau-geung until it is merged. Run ./scripts/install.sh from a checkout of that branch, or set update_branch = "gau-geung" in ~/.mogeung/config.toml so the updater follows it.
Your homes are never writtenNothing is written under ~/.claude, ~/.claude.json, ~/.codex, ~/.qwen or opencode's directories, ever. A seat is configured through its CLI's own flags at launch; everything it needs kept lives under ~/.mogeung. A seat that needs a home of its own gets one there, opt-in, per seat.

Define a team

Open the Teams window with Alt+Shift+G (⌥⇧G on a Mac) or the Users button in the top bar. It opens in a window of its own, which you can move beside mogeung, resize, and zoom with Ctrl+= / Ctrl+- inside it; the main window dims until you close it, and pressing the chord again brings it forward. Press New team and fill the two layers.

The team layer

  • name and repository: an absolute path. Worktrees are made from it.
  • team guidance: every seat gets this, before its own.
  • default permission mode: default, acceptEdits, plan or bypassPermissions, in Claude Code's words. The launcher maps each to every CLI's own flag.
  • policy: the hop budget (3), sends per hour (60), the handover rule, the readiness press, and the declared wakes and watchdogs. Every automatic send a team can make is written here, in text you can read before it ever fires.

The seat layer

  • name: lower-case letters, digits and dashes. It names the worktree, the tmux session and the address a teammate sends to.
  • cli and model (the CLI's own spelling, or its default).
  • works in: a fresh worktree on branch geung/<team>/<seat>, or the team's own checkout, where nothing of mogeung's is ever written.
  • permission: inherit the team's, or override it. Codex has no plan mode and is refused that one by name.
  • guidance: added after the team's.
  • a home of its own: a blank home under ~/.mogeung, with its own login and none of your skills, plugins, memory or MCP servers. A Qwen seat needs one to be hooked.

Save is grey with the daemon's own sentence while the definition cannot be addressed: a bad seat name, two seats with one name, a wake aimed at a seat the team lacks, a cap of zero. The daemon validates again on Save and mirrors the definition as markdown under ~/.mogeung/teams/.

Boot and stop

Boot team starts every seat that is not running, each in a tmux session of its own named geung-<team>-<seat>. A seat that is running is left alone; one that exited is started again. The button says beforehand which seats it would start and is grey when every seat is running; once the daemon has answered, the window closes and a notice says what started. A seat's row is on the queue from birth, marked with its team and seat, under a collapsible Team section at the top of the Attention list with a heading per team, apart from the sessions you started yourself. The Teams window shows where each seat runs. What a boot makes, and where:

whatwhere
the worktree~/.mogeung/worktrees/<repo>/<team>-<seat>, branch geung/<team>/<seat>; found again on the next boot, left behind at stop
the seat's files~/.mogeung/seats/<team-id>/<seat>/: guidance.md, hook.sh, settings.json or mogeung-plugin.js, bin/mogeung-send, signals.jsonl, and home/ when asked for
the team's tmux sessiongeung-<team>: every seat tiled in one window, and a window per seat. tmux attach -t geung-<team> from any terminal; the mode offers the command to copy
the recordin the daemon's store, so a restarted daemon re-adopts its seats

What each CLI is handed, and whether it comes back hooked:

CLIlaunchsignals
Claude Code--session-id, --permission-mode, --append-system-prompt-file, --settings with seven hooks and a status linehooked with curl; plain without
opencodeinline config with the guidance, the mode and a plugin filehooked (the plugin posts from inside the CLI)
Qwen Code--session-id, --approval-mode, --append-system-prompt; hooks in the settings of a home of its ownhooked only with a home of its own; plain otherwise
Codex-a, -s workspace-write; guidance as a marked block in the worktree's AGENTS.md, taken back at stopplain always; its hooks live in a config format nobody here has read

A Codex seat in the team's checkout cannot be given guidance without writing there, so it is refused in words: put it in a worktree, or give it a home of its own.

Stop team ends every seat's process and forgets the records. The worktrees stay. remove worktree is a separate click on a stopped seat, and it refuses a dirty tree and tells you what is in it; the branch stays either way.

A hooked seat's status line shows what the daemon knows: port/reviewer · a seat of mogeung's · hops 1/3 · 4/60 this hour.

The board

Alt+G (⌥G on a Mac), or the network button in the top bar, opens the team board as a pane in the main tile tree, beside whatever you have open; pressed again while the board is in front, it closes it. The Attention list, the rail and Alt+A's chat stay where they are. Nothing is fetched: the board is a different reading of what the window already holds. Across its top, a tab per team and one for all of them, with each team's counters and whether it is paused. Picking a seat opens the seat pane beside the board; Attach terminal adds a terminal pane for that seat. All three are ordinary panes: drag, split, tab and pop them out as you do any other, and they are saved with the rest of your layout.

The board shows, per team: the pulse, the topology, and the policy strip.

The five lanes

The pulse sorts a team's seats into OpenRig's five lanes. Each card carries mogeung's own badge inside it, the same one the queue shows.

Needs you

an approval, an error, a limit, a held message, or idle with nothing in hand

Parked with baton

idle after a message arrived: it holds the baton and has not passed it on

Blocked on agents

idle after sending: waiting on the seat it told

Now

working

Just finished

exited, or stopped; the worktree stays

Two idle seats look the same on the queue. The send log is what tells parked from blocked, and the lane is the thing the mode knows that the queue does not.

Below the pulse, the topology shows the graph and the table of the same seats, together. An edge is the last send between two seats; a held edge is a message waiting for you, with the hop number on it. The table names each seat's CLI and model, worktree and branch, state and its source, context fill, tokens, sends in and out, and when anything last happened. Every state says where it came from: (hook), (plugin), (transcript) or (screen), and a Codex seat's context reads unknown · no hooks rather than a guess.

A seat's pane

Click a card, a node or a row and the seat pane shows that seat: its identity line, its state, what its hooks have said, what its pane showed, its last sends, its tokens and diff, and what it was launched with. The buttons:

  • Attach terminal: a terminal pane in the mode, attached to the seat's own tmux pane. Typing goes to the seat.
  • Select underneath: select the seat's session in the window below, for its transcript, diff and Agent pane.
  • Restart with handover: stop the seat and start it again, with a handover composed as the policy says.
  • A held handover shows whole, with Deliver and Discard.

Terminals

Each seat terminal is a pane of its own, attached on its own, like the Agent pane. Keys go to the pane you clicked; every pane keeps rendering. For a terminal of your own, tmux attach -t geung-<team> gives the daemon's grouped layout: window all with every seat tiled, then a window per seat for the full screen. The window does not mirror that layout; the two pictures differ on purpose.

How seats talk

Every seat with curl is handed mogeung-send on its PATH and a paragraph at the end of its guidance naming its team, its teammates and the command. A seat runs:

mogeung-send reviewer "tests pass on wt/builder — please review src/seat.rs"
echo "done" | mogeung-send planner

The daemon judges the message against the team's policy and types it into the teammate's pane, once, as a person would. The one line it answers is printed, and the exit code says which:

exitmeaning
0delivered: delivered to `reviewer` — hop 2 of 3
2held for a human: the hop budget is spent, the cap is reached, or the team is paused. Not lost: you release or drop it
1refused: a seat outside the team, itself, one not running, nothing to say

A seat talks only to seats of its own team. A name outside it is refused with the team's seats listed; two teams that must talk are one team, or they talk through you.

The budget and the switch

Every automatic send is visible, budgeted and stoppable. The policy strip on the board and the Teams window both show the counters: hops 2/3 · 23/60 this hour.

  • Hop budget (default 3): how many agent-to-agent deliveries may run in a row with no human between. A seat's message and a wake are hops; a watchdog's nudge is not. The next hop past the budget is held, and the seat it was for ranks on the queue as needing you. Your own send into any seat, or a release, starts the count again. Zero means every message goes through you.
  • Sends per hour (default 60): every automatic kind counts; the next past the cap is held. The hour slides.
  • Pause: one switch per team, in the Teams window and on the board. It acts at once, every automatic send is held while it is on, and typing in a pane always works. Saving a definition never flips it.

A held send sits on the recipient's row as the reason it needs you, and in the Teams window and the board with release (type it now; your act, so the chain starts again) and drop (never deliver it). The send log keeps the last two hundred entries per team: who, whom, the text, why, what became of it, and the hop it took.

Wakes and watchdogs

Both are declared text in the policy, readable before they fire.

  • A wake says: when seat A does X, tell seat B this. X is Stop (the seat finished a turn, from its hook, or for a plain seat from its registry going idle) or Exit (its process ended). A wake is a hop.
  • A watchdog says: a seat silent for N minutes, while busy if you say so, is told this. Once per silence. A watchdog is not a hop, and still counts against the hour.

Your own sends

Your send into a seat is what it has always been: the follow-up prompt window's send it, or typing in the Agent pane, with the confirmation it has always had. It is logged beside the automatic ones as you, never counts against the hour, and starts the chain again. A session you started by hand has no ledger at all; nothing in the policy can reach it.

Handovers

When a seat joins a team whose other seats have already worked, or is restarted, the daemon asks your configured model to compose a handover: what the team is doing, what the others did and where they stopped, what this seat should pick up first. It is composed from the team's guidance, the teammates' last turns and diffs, the send log, and on a restart the seat's own earlier session, every line of it framed as data another agent wrote. The policy's handover setting decides what happens next:

settingbehaviour
after you read itcomposed and held on the seat's row until you press Deliver or Discard. The default
deliver automaticallycomposed and typed as an automatic send, a hop, counted against the cap
nonenothing is composed; the seat starts cold

The entry is logged composed by <model> @ <host> and shown whole in the seat pane. With no model endpoint configured, or a host you have not consented to, a refusal entry says the seat started without one. A cold boot, where nobody has done anything yet, hands over nothing.

What the screen says

A seat's pane is read each scan into a closed set of shapes, and only a seat's: the capture takes a pane from the launch record and nowhere else, so no pane you opened yourself is ever captured. The capture is never kept; what reaches the row is the shape, the few lines it was read from, and when.

shaperanks as
permission menu, plan approval, questionAPPROVE permission menu (screen)
trust dialog, login, press EnterWAITING, named: these are yours to answer in the pane
rate limitLIMIT
exited to a shellFAILED
at the prompt, working, unknownnothing: the quiet shapes never rank, and unknown is a value, never a guess

A hook's fact outranks a screen's reading, so (screen) appears only where the evidence was silent. A screen that matches nothing raises screen:<cli> in the Health window, which is how a CLI release that restyles its menu will be noticed.

The readiness pressThe one press mogeung may make is Enter, for the one shape that asks for it, and only when the team's readiness press is on. It is off by default and should stay off until a week of captures says the shape is read reliably. mogeung never answers a permission menu, a question, a trust dialog or a login from a reading.

Editing in a worktree

A file of a seat's worktree opens editable in the file pane, and the header says so. Everything else stays a viewer: your own sessions, a seat in the team's checkout, a revision, a file cut short by the size cap. Save with Ctrl+S or the button. Two refusals, and the pane shows which:

  • The file changed on disk since you opened it: an agent wrote under you. The pane says how many lines theirs and yours differ on and offers reload theirs. There is no override; reload and make your edit again.
  • The seat is mid-turn in this worktree: a save now lands under a working agent. Wait, or save anyway, on that save only.

Your draft stays on screen while the file reloads under you, and the save carries the version you began from, so the daemon catches the race rather than you.

Import and export

Export… on a saved team writes its definition whole as JSON where you choose, or beside the markdown mirror under ~/.mogeung/teams/. Import… reads a file and answers a draft, never a save: review it, set the repository, press Save.

filebecomes
mogeung's .jsona new team: the id is dropped, the stamps zeroed, the pause cleared
OpenRig rig.yamlmembers become seats by runtime (a runtime that is not a CLI is skipped and said so); agent_ref is followed beside the rig to the agent's guidance; the summary and culture file become the team's guidance; edges are carried as text, not as wakes; profiles, skills, plugins and startup actions are listed as not carried

What mogeung never does

  • Adopt a session as a seat. Birth decides ownership. The session in your own terminal keeps every promise it always had.
  • Write under your agent homes. Not a settings key, not a hook, not a plugin. A home of mogeung's own is opt-in, per seat, under ~/.mogeung.
  • Send to a session you started by hand. The one function that types into a seat takes a launch record and nothing else.
  • Compose a wake or a watchdog. Automatic sends are declared text. The handover is the one exception, and it is shown whole and logged as the model's.
  • Answer a gate from a screen reading. A permission menu is the seat's permission mode, chosen at launch. Trust and login are yours.
  • Let a seat reach another team. A team is the unit of policy, and a delivery across two policies is refused rather than counted twice.
  • Run past the budget quietly. The fourth hop in a chain is held and ranks as needing you; so is the sixty-first send in an hour.
  • Write a worktree it did not make. The file pane saves in a seat's worktree only, and refuses a moved file and a busy seat.

Troubleshooting

you seewhy, and what to do
a seat says plainits CLI carries no hooks (Codex), or it is Qwen without a home of its own, or curl is missing. A plain seat still works; it cannot run mogeung-send without curl
no geung-<team> sessiontmux refused the layout; the seats are up and the daemon logged why. The window reaches each seat regardless
a handover entry reads refusedno model endpoint is configured, the host is not consented to, or the endpoint failed; the note says which. Set model_url and allow_remote_model in ~/.mogeung/config.toml
screen:claude in Healtha seat's pane showed something the closed set does not name. Attach the terminal and look; a restyled menu is a fixture to pin
hook:Something in Healtha seat posted a hook event nobody has classified. Nothing was dropped; it is a decision to take
a seat keeps getting heldthe chain hit the budget. Release it, send something yourself, or raise the budget in the policy. If you keep raising it, zero is the honest setting
Boot is greysave the team first; a dirty draft is not what Boot starts. Or the window is dialled in from another machine on a daemon without --allow-run
remove worktree refusesthe tree is dirty. Commit or discard in it first; the branch stays
